# ghacc 交互式数字菜单设计

## 目标

为新手提供无需记忆子命令的菜单界面。用户运行 `ghacc` 后输入数字并回车即可执行常用操作；所有现有子命令和自动化行为保持兼容。

## 入口行为

### 交互终端

当 `stdin` 和 `stdout` 都是终端，且运行 `ghacc` 时没有提供参数，默认进入菜单。

### 显式菜单

新增子命令：

```bash
ghacc menu
```

无论是否为终端都允许显式调用，便于测试和高级用户使用。`menu` 不接受额外参数。

### 非交互环境

运行 `ghacc` 且没有参数，但 `stdin` 或 `stdout` 不是终端时，显示命令行帮助并返回 0。这样可以避免自动化、CI、cron 或管道调用被菜单挂起。

## 兼容性

所有现有命令保持不变，包括：

```bash
ghacc clone <github-url>
ghacc pull
ghacc fetch
ghacc git <git-arguments...>
ghacc download <github-url>
ghacc archive <owner/repo> [ref]
ghacc release <owner/repo> <tag|latest> [asset-pattern]
ghacc update
ghacc install-timer
ghacc uninstall-timer
ghacc status
ghacc help
```

`ghacc menu` 是新增子命令。现有脚本参数、退出码语义和直连回退行为不变。

## 菜单结构

```text
ghacc 菜单

  1) 克隆 GitHub 仓库
  2) 拉取当前仓库更新
  3) 抓取当前仓库远端
  4) 下载 GitHub 文件
  5) 下载源码压缩包
  6) 下载 Release 资产
  7) 更新镜像订阅缓存
  8) 安装并启用定时更新
  9) 停用并卸载定时更新
 10) 查看加速源和定时器状态
 11) 高级 Git 命令
 12) 显示命令行帮助
  0) 退出

请输入数字后按回车:
```

菜单显示到 stdout；日志和命令输出继续按现有行为输出。这样便于用户区分菜单提示和底层 Git/curl 输出。

## 菜单动作

### 1. 克隆 GitHub 仓库

提示输入 GitHub 仓库地址。空输入不执行并返回菜单。地址会传给现有 `clone_command`。

### 2. 拉取当前仓库更新

无额外提示，直接调用现有 `pull_command`。必须在 Git 仓库内执行；失败信息由现有命令提供。

### 3. 抓取当前仓库远端

无额外提示，直接调用现有 `fetch_command`。必须在 Git 仓库内执行。

### 4. 下载 GitHub 文件

提示输入 GitHub 文件 URL。空输入不执行并返回菜单。URL 传给现有 `download_command`。

### 5. 下载源码压缩包

提示输入：

- `owner/repo`，必填
- 分支、标签或提交，可留空，默认 `HEAD`

输入传给现有 `archive_command`。

### 6. 下载 Release 资产

提示输入：

- `owner/repo`，必填
- 版本号或 `latest`，可留空，默认 `latest`
- 资产名称或关键词，可留空；留空时列出版本资产而不下载

输入传给现有 `release_command`。

### 7. 更新镜像订阅缓存

无额外提示，调用现有 `update_command`。订阅失败时保留旧缓存，菜单显示失败和退出码。

### 8. 安装并启用定时更新

这是系统级操作。菜单先显示说明，并要求输入 `y` 或 `Y` 确认；其他输入不执行并返回菜单。

脚本不自动提权。如果当前用户不是 root，菜单显示建议命令：

```bash
sudo ghacc install-timer
```

不执行自动 `sudo`，避免意外修改系统配置。

### 9. 停用并卸载定时更新

同样是系统级操作，要求输入 `y` 或 `Y` 确认。非 root 时显示建议命令：

```bash
sudo ghacc uninstall-timer
```

不自动提权。

### 10. 查看状态

调用现有 `status_command`。

### 11. 高级 Git 命令

提示输入 Git 参数，例如：

```text
pull origin main
```

菜单使用 Bash 数组按空白拆分输入后传给现有 `git_command`。该入口面向高级用法；参数值本身包含空格的场景应直接使用 `ghacc git ...`。

### 12. 显示帮助

调用现有 `usage`。

### 0. 退出

返回 0。

## 结果反馈与循环

每个动作结束后捕获并显示退出码：

```text
操作完成，退出码: 0
```

或：

```text
操作失败，退出码: 128
```

随后提示：

```text
按回车返回菜单...
```

菜单不会把底层命令失败隐藏成成功；菜单进程自身只有在选择退出、EOF、非法持续输入策略触发或致命错误时退出。

## 输入与键盘可访问性

- 菜单使用普通 stdin/stdout 文本，不使用终端控制库、颜色状态或图形组件。
- 用户必须输入数字并按回车才会执行动作；数字浏览或高亮不会触发操作。
- 提供明确的 `0) 退出`。
- 所有提示都有文字标签，不依赖颜色或图形符号。
- EOF 视为退出，返回 0。
- 非数字或未知数字显示“无效选择”，并重新显示菜单；不执行任何真实操作。

## 无障碍与新手体验

- 数字项和中文动作名在同一行，说明简短清晰。
- 系统级操作先显示影响，再要求显式确认。
- 需要输入的字段说明可留空时的默认值。
- 操作结果显示明确的成功/失败和退出码，不依赖颜色。
- 不自动提权、不后台静默修改系统。

## 测试策略

使用确定性 Bash 集成测试：

- 显式 `ghacc menu` 配合受控 stdin 测试菜单输出和动作分发。
- 通过 PATH stub 验证菜单调用的是现有命令函数对应的 CLI 分发路径。
- 测试常见路径：克隆、下载、archive、release、update、status、高级 Git。
- 测试空输入、非法数字、EOF、操作失败后返回菜单。
- 测试系统级菜单的 `y/Y` 确认、非确认输入和非 root 提示。
- 测试 `ghacc` 无参数时交互终端进入菜单、非交互终端显示帮助。
- 保持现有 62 项测试全部通过，不访问网络和真实 systemd。

## 验收标准

- 在 Linux 交互终端运行 `ghacc` 直接显示菜单。
- `ghacc menu` 可显式进入菜单。
- 数字加回车执行对应操作，动作后返回菜单。
- 菜单失败不会掩盖底层退出码。
- 现有子命令、参数处理和退出码不变。
- `ghacc` 无参数在非交互环境显示帮助，不阻塞。
- 系统级操作必须显式确认且不自动提权。
- Bash 语法检查和全部确定性测试通过。

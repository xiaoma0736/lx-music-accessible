# 批量下载选中歌曲与下载限制设计

日期：2026-10-07  
状态：已获用户批准，待实现

## 目标

在现有歌曲列表中提供明确的批量下载入口，只下载用户显式选中的歌曲，并提供任务频率与传输速度限制，降低音源和 API 风控压力。功能必须保持 WinForms 原生键盘操作、焦点可预测性和屏幕阅读器可感知反馈。

## 范围

本设计覆盖以下四个已存在的主窗口歌曲列表：

- 搜索歌曲列表：`SearchResults`
- 专辑/分类歌曲列表：`CategorySongs`
- 播放列表/收藏歌曲列表：`FavoriteSongs`
- 排行榜歌曲列表：`RankingSongs`

不覆盖播放列表名称列表、专辑名称列表或排行榜名称列表；这些列表仍用于选择一个专辑、歌单或榜单，不直接批量下载。功能不会自动展开分页、不会自动下载整个专辑/歌单/榜单，也不会自动加载更多歌曲。

## 列表多选与键盘语义

四个歌曲列表使用 `ListBox.SelectionMode = SelectionMode.MultiSimple`，继续使用传统 WinForms `ListBox` 和 `ContextMenu`，不引入自定义列表控件。

键盘行为如下：

- `Up` / `Down`：移动焦点；焦点移动不选择歌曲、不触发下载、播放或其他网络操作。
- `Ctrl+Space`：切换当前焦点歌曲的选中状态。
- `Ctrl+A`：选中当前列表中的全部歌曲。
- `Enter`：播放当前焦点歌曲。
- `Shift+Enter`：打开当前焦点歌曲歌词。
- `Space`：播放/暂停播放。
- `Application` 键或 `Shift+F10`：打开原生右键菜单。
- `Esc` 继续遵循现有主窗口搜索清空与桌面隐藏规则，不新增列表级歧义行为。

实现必须确保 `Ctrl+Space` 用于选择切换，普通 `Space` 保持播放/暂停；不得让现有 `Space` 处理器吞掉 `Ctrl+Space`。列表选中状态变化不得触发下载。右键或菜单键打开菜单本身不得改变选中集合、不得触发网络请求。

屏幕阅读器继续读取原生 ListBox 的项文本和选中状态。菜单项文本是命令的无障碍名称，选中数量必须直接出现在文本中。

## 右键菜单

现有菜单中的“下载”改名为“下载当前歌曲”，语义是只处理当前焦点/选中的一首歌。

新增菜单项：

- 文本：`批量下载选中歌曲(N)`
- `N` 是当前选中歌曲数量。
- 选中数量少于 2 时禁用。
- 命令只会提交当前列表中显式选中的歌曲。
- 命令执行后源列表焦点和选中集合保持不变。
- 菜单使用传统 `ContextMenu` / `MenuItem`，不使用 `ContextMenuStrip`。

命令调用现有 `DownloadListAsync` 批量工作流，不绕过下载管理、任务队列、取消、重试和文件安全逻辑。`DownloadListRequest.Label` 使用能描述来源的稳定文本，例如“选中歌曲”“专辑歌曲”“播放列表歌曲”“排行榜歌曲”。

## 下载执行与限制

批量下载固定逐首串行执行，不引入并发下载。单个下载仍复用 `DownloadWorkflow.ExecuteManagedAsync` 的解析、下载、歌词、原子写入、冲突、取消和清理路径。

新增两个持久化设置：

### 1. 批量下载间隔

- 设置名：`BatchDownloadDelaySeconds`
- 用户可见名称：`批量下载间隔（秒）`
- 类型：整数
- 默认值：2
- 范围：0 到 60
- 行为：前一首任务终态后，若还有下一首，则等待该间隔再开始下一首。最后一首之后不追加等待。
- 等待必须响应应用退出和用户取消；超时等待取消后不得继续解析或下载下一首。

### 2. 下载限速

- 设置名：`DownloadSpeedLimitKbps`
- 用户可见名称：`下载限速（KB/s，0 表示不限速）`
- 类型：整数
- 默认值：0
- 范围：0 表示不限速；非零范围为 32 到 100000
- 行为：限制音频响应体的读取/写入速率，单位为 KB/s，按 1024 字节计算。
- 单曲下载和批量下载共用该传输限速；源解析、歌词解析等 API 请求不按字节的传输限速处理，其频率由批量间隔和串行执行控制。

限速实现必须支持取消，不得通过长时间阻塞线程实现，也不得破坏现有进度事件和退出流程。

## 设置界面与持久化

在设置窗体“下载”页新增两个 `NumericUpDown` 控件：

- `批量下载间隔（秒）`
- `下载限速（KB/s，0 表示不限速）`

每个可聚焦控件必须有简洁语义 `AccessibleName`、明确 `TabIndex`，并保留标准键盘操作。修改后立即应用到工作流并持久化，与现有下载设置一致。设置持久化模型需要保留旧数据兼容：旧 JSON 缺少新字段时使用上述默认值。

启动时设置工作流必须把越界值规范化到合法范围，并把规范化结果写回当前运行状态；不得让损坏配置绕过限制。

## 无障碍反馈

所有开始、结束、失败、取消和跳过反馈继续走现有全局播报通道，同时保留播报行文本镜像。批量开始和结束消息必须包含来源标签和数量摘要。

结束消息示例：

- `批量下载选中歌曲结束：成功 4 首，失败 1 首，取消 0 首，跳过 0 首`

一次命令只播报一条命令结果，不重复朗读焦点变化或列表刷新。后台批量过程中，下载管理器中的单项进度继续由下载管理器呈现；主窗口不得因为进度变化抢占焦点。

## 错误、取消与退出

- 空列表或选中数不足时菜单禁用；不会提交空批量请求。
- 单首失败不阻断后续歌曲。
- 用户取消当前任务后，批量序列停止，剩余歌曲计为跳过。
- 应用退出时继续由统一关闭流程停止后台任务，不得遗留下载进程或未完成写入。
- 文件路径安全、重名处理和临时文件清理继续由 `DownloadWorkflow` 独占，不在 UI 层复制。

## 验收标准

- 四个歌曲列表均可只用键盘完成多选、查看选中数量并通过右键菜单批量下载。
- 普通 `Space`、`Enter`、`Shift+Enter` 和方向键行为保持不变；`Ctrl+Space` 与 `Ctrl+A` 可可靠改变选择。
- 选中少于 2 首时批量菜单禁用；选中 2 首及以上时只提交显式选中集合。
- 批量执行严格串行；除最后一首外，相邻任务之间遵守配置间隔。
- 限速值 0 表示不限速，非零值按 KB/s 生效，并可取消。
- 设置立即生效、持久化，重启后仍然有效；越界持久化值被规范化。
- 所有状态变化有文本镜像播报；焦点不因后台进度或批量结束被抢占。
- 自动化测试覆盖选择键盘路径、菜单状态、批量请求内容、串行间隔、取消、限速、设置边界与持久化。
- 仓库本地 `verify.ps1` 质量门通过。

# 音源声明音质与下载流程修复设计

## 背景

当前音质子菜单会为每个候选接口解析播放链接，并下载前 256 KB 媒体数据推断真实格式/码率。该行为把“音源声明提供的品质”和“媒体真实性验证”混在一起，导致菜单延迟、外部 CDN 拒绝探测请求时误报不可用，下载阶段还会再次嗅探真实格式并触发回退/拒绝。

同时，歌曲菜单存在“下载当前歌曲”直连入口和“下载单曲音质”子菜单两条路径，容易让用户混淆。批量下载和专辑下载需要重新审查，保证任务顺序、取消、分页和目录语义一致。

## 目标

1. 项目代码回滚到 GitHub `origin/main` 当前状态，彻底移除本地汽水音乐实现。
2. 音质菜单只展示当前歌曲平台在可用音源接口中声明的音质。
3. 不解析 URL、不下载媒体、不校验媒体真实性来完成音质可用性判断。
4. “下载单曲音质”子菜单是唯一的当前歌曲下载入口；选择具体音质后立即创建下载任务。
5. 单曲下载只请求用户选择的确切音质，不自动向更高或更低音质回退。
6. 下载阶段信任音源声明的音质，不再下载后嗅探真实音质并拒绝。
7. 批量下载保持串行、可取消、有间隔，并避免多个批量任务并发执行。
8. 专辑下载先加载完整专辑分页，再按专辑名子目录提交一次批量下载。
9. 所有入口保持键盘和屏幕阅读器可用，状态提示明确。

## 非目标

- 不验证音源返回媒体的真实码率、容器或标签。
- 不修改播放内核或外部播放器流程。
- 不新增音源接口。
- 不尝试恢复或保留汽水音乐相关代码。

## 架构

### 音质探测

`QualityProbeWorkflow` 改为基于 `IQualityCandidateSource.GetCandidatesAsync()` 的同步语义查询：

- `GetCandidatesAsync` 已按当前默认音源优先，并在默认音源不支持歌曲平台时回退到该平台全部可用接口。
- 探测工作流按品质 rank 排序、去重并生成 `QualityOption`。
- 每个声明音质返回 `Playable`，接口名取该组候选中优先级最高的接口。
- `ActualQuality` 与 `DownloadQuality` 保持空值，菜单不再显示“实际音质”。
- 移除 HTTP 客户端、Range 请求、并发探测、媒体数据缓存和真实性判断。
- 缓存只保留同一歌曲的声明结果；音源列表变化后由现有生命周期触发失效。

### 下载

`DownloadWorkflow` 的远程下载流程调整为：

1. 查询歌曲所属平台当前声明的候选音质。
2. 校验请求音质已声明；未声明则任务失败并提示“音源未声明所选音质”。
3. 只解析请求音质的播放 URL。
4. 下载完整媒体并保存；不做真实格式/码率校验。
5. URL 解析或网络传输失败时任务失败，不回退到其他品质。

为了保持适配层清晰，`IDownloadSource` 增加按歌曲获取声明音质的接口。`DownloadSourceAdapter` 复用音源服务中的候选声明逻辑，避免下载和菜单使用两套音质集合。

### 用户界面

- 主菜单移除“下载当前歌曲”和 `F2` 直连下载。
- 歌曲右键菜单移除“下载当前歌曲”。
- “下载单曲音质”子菜单直接列出声明音质。
- 可用音质菜单项文案为“<音质>，可下载，<接口>”。
- 回车或点击菜单项后立即调用 `DownloadAsync(new DownloadRequest(song, quality))`。
- 状态提示继续使用可去重的 activity id，避免读屏重复播报。

### 批量与专辑

- 批量下载入口继续提交 `DownloadListAsync`。
- `download.list` 槽位确保新批量任务取消旧批量任务。
- 批量循环保持逐首执行、歌曲间隔、取消检查和终端汇总。
- 专辑下载加载所有分页后合并歌曲，使用专辑标题作为 `Subdirectory`，一次性提交批量任务。
- 加载中禁止重复触发；失败和空专辑提供明确无障碍提示。

## 测试策略

按测试驱动开发执行，先更新/新增失败测试，再实现：

- 音质探测：只调用候选声明接口；不发起 HTTP；输出顺序与接口名正确。
- 菜单：无“下载当前歌曲”项；下载子菜单选项触发精确音质下载。
- 下载：已声明音质下载成功；未声明音质不请求 URL；下载错误不回退。
- 批量：串行执行、延迟、取消和结果统计。
- 专辑：分页合并、子目录、一次任务提交与加载中防护。
- 回归：完整测试套件通过，发布打包通过。

## 验收标准

- `git diff origin/main` 不包含汽水音乐代码。
- `QualityProbeWorkflow` 不再引用 `HttpClient` 或媒体下载探测。
- 歌曲菜单和文档中不存在“下载当前歌曲”入口。
- 音质菜单内容完全来自音源声明。
- 单曲、批量、专辑下载测试全部通过。
- 完整测试和打包验证通过。

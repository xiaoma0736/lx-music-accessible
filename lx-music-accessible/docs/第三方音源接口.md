# 第三方音源接口说明

本文件梳理「落雪音乐无障碍版」对第三方音源（LX Music 自定义源脚本）的支持范围，
接口契约对齐原版 `lx-music-desktop`（`src/common/types/user_api.d.ts` 与
`src/main/modules/userApi/renderer/preload.js`）。

## 1. 音源脚本如何工作

一个已验证且已启用的音源脚本（.js）在需要时被加载，脚本通过 `globalThis.lx` 运行时注册能力：

1. 调用 `lx.on(lx.EVENT_NAMES.request, handler)` 注册请求处理器，或定义
   `handleGetMusicUrl(source, musicInfo, type)`（旧式）；
2. 调用 `lx.send(lx.EVENT_NAMES.inited, { sources })` 声明支持的平台、动作与音质；
3. 应用在需要播放/歌词/封面时，向处理器发 `{ source, action, info }`，脚本返回
   Promise，结果为 URL 字符串或歌词对象。

## 2. 接口类型（动作）

| 动作 action | 说明 | 返回 | 校验规则（对齐原版） |
| --- | --- | --- | --- |
| `musicUrl` | 解析播放地址 | `string` | 必须为 `http(s)` 且长度 ≤ 2048 |
| `lyric` | 解析歌词 | 对象 | `{ lyric≤51200, tlyric≤5120, rlyric≤5120, lxlyric≤8192 }`，`lyric` 必须为非空字符串 |
| `pic` | 解析封面 | `string` | 必须为 `http(s)` 且长度 ≤ 2048 |

平台 id：`kw`（酷我）、`kg`（酷狗）、`tx`（QQ）、`wy`（网易）、`mg`（咪咕）；
本应用内部 id 映射：`qq↔tx`、`netease↔wy`、`migu↔mg`。

## 3. 运行时 API（`globalThis.lx`）

| 成员 | 说明 |
| --- | --- |
| `EVENT_NAMES` | `{ request, inited, updateAlert }` |
| `on(name, handler)` | 注册处理器（当前支持 `request`） |
| `send(name, data)` | 发送事件（`inited` 接受；`updateAlert` 会上抛给界面提示） |
| `request(url, options, callback)` | HTTP 请求；`options` 支持 `method/timeout/headers/body/form/formData`；返回取消函数；回调 `(err, resp)`，`resp` 含 `statusCode/statusMessage/headers/bytes/raw/body` |
| `utils.crypto` | `aesEncrypt(buffer,mode,key,iv)`、`aesDecrypt(...)`、`rsaEncrypt(buffer,key)`、`randomBytes(size)`、`md5(str)` |
| `utils.buffer` | `from(...)`、`bufToString(buf, format)` |
| `utils.zlib` | `inflate(buf)`→Promise、`deflate(data)`→Promise（zlib 格式） |
| `env` | `"desktop"` |
| `version` | `"2.0.0"` |
| `currentScriptInfo` | 当前脚本 `{name, description, version, author, homepage, rawScript}` |

另外提供常用全局：`Buffer`、`fetch`（Promise 封装）、`window/global/self`、
`navigator`、`location`、`process`、`crypto.getRandomValues`、CommonJS `require/module/exports`
与 AMD `define`（含 `httpFetch` 依赖注入）。

## 4. 本应用实现

- `LxScriptEngine`（Services）— Jint 引擎 + JS shim，忠实执行混淆脚本；
  正则快路径（`ScriptMusicSource`）识别不了的一律走 Jint。
- 播放 URL 解析顺序：默认源 → 其余已启用脚本源（按优先级，仅尝试支持当前平台的脚本）
  → 内置官方 API（同平台）→ 失败后跨平台严格匹配换源（见 `MusicSearchMatcher`）。
- 应用随版本嵌入一份固定备用源及其 SHA-256 摘要，离线时仍有可用脚本。窗口显示后，受控后台任务会刷新历史产品清单中的 4 个固定订阅地址（HYW、聚合 API、全豆要、念心）；不会根据远程清单或持久化的任意地址自动扩展订阅范围。
- 订阅候选仍受 HTTPS/公开网络目标、15 秒超时、1 MiB 脚本大小、严格 UTF-8、重定向与 Jint 执行预算约束。候选只有在解析和注册处理器检查成功后才会建立内容摘要、自动信任、启用并持久化；已有可信源的显式禁用状态保持不变。单条下载、校验或持久化失败会保留上一可信版本，并继续刷新其他订阅。
- 用户从网络或本地发起导入即表示信任该次取得的内容；应用先校验脚本与摘要，成功后自动信任、启用并持久化，失败内容不会进入执行器。非固定订阅的同一 URL 后续变化只有在用户再次导入时才会重新校验和启用。
- 旧版本留下且缺失信任元数据的有效脚本会用现有持久化内容建立摘要并自动启用；除上述固定订阅外不会回源下载。内容缺失或已有摘要不匹配时不会进入执行器。已经具有可信元数据且被用户禁用的脚本保持禁用。
